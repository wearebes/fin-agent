# 研究报告生成超时修复

2026-09-01。用户原研究为腾讯最近两个已披露完整财年的经营现金流、资本开支及回购分析。

## 根因与修改

1. 原研究已成功收集 45 条证据，进入报告生成后触发 Codex 的 90 秒超时。模型短测试成功只能证明连接，不能证明长报告能在此时限内完成。现将生成默认时限设为 300 秒，启动时限单独保持 30 秒，不移除超时保护、不改变访问权限、不自动切换其他 API。
2. 原证据提示按旧记录顺序装满 60,000 字符后停止，遗漏最后 15 条证据，包括后面新找到的腾讯官方来源。这会让后续工具决策看不到新结果。现优先呈现新收集的证据，去掉完全相同的副本；某条记录放不下时继续检查后面的记录，仍保留整条记录和明确的省略数量，不裁断财务数字，不修改原始证据存储。新收集不等于财务期间更新，日期核验约束仍保留。
3. Codex 请求增加默认 4096 输出 token 的提示预算，实际为软约束，不是服务端硬截断。启动、报告超时、连接错误分别处理；过滤 Codex 的中间说明文本，避免混入要求 JSON 的最终输出。
4. 中文界面现在明确显示“模型响应超时，资料已保留”。失败时不再写出误导性的“Generated report”过程记录，也不记录供应商原始异常内容。

未新增依赖，未替换任何金融数据接口，未修改客户 API 的地址、鉴权或访问隔离。

## 真实验证

使用生产 Codex 适配器和原 `synthesize` / `review` 阶段，复用原失败记录保存的 45 条证据；没有模拟模型，没有重新运行计划或取数，没有调用方舟等其他 API。
