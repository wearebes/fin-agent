## 已实现

- 本机通过官方 `codex app-server` 的私有标准输入输出连接已登录的 ChatGPT 账户，不提取、复制登录令牌，不建立额外网络监听端口。
- Codex 仅向明确指定的 Fin-agent 账户开放；还必须从本机、同源页面访问。拒绝其他用户、远程地址、转发头和第三方网页来源。默认关闭，不会把第一个注册用户自动设为所有者。
- 每次调用使用临时目录、临时线程和禁止审批的权限配置。禁止读取临时工作区以外的文件，禁用命令、MCP、应用、插件、浏览器及其他非文本工具；权限配置未生效时停止调用。
- Codex 单进程限制并发，超时或客户端断开时关闭连接进程，不自动改用其他 API。Windows 下沿用已有系统 HTTPS 代理，不修改系统或 Codex 全局设置。
- 原有个人 API 接入继续可用：OpenAI、DeepSeek、通义千问、智谱、Kimi、豆包、Gemini、Claude，以及管理员批准域名上的兼容服务。支持 OpenAI Chat Completions 与 Anthropic Messages 两种协议；不代表任意专有协议都可直接接入。
- 个人密钥仍按用户独立保存在服务端内存，24 小时或服务重启后失效，不写入前端存储、报告或配置。研究结果与过程查询增加所属账户校验。
- 商业模式关闭个人 Codex 和公共系统模型入口；即便服务器有系统 API Key，也不会通过这两个网页研究入口使用它。商业模式要求持久化 SQL、至少 32 字符的独立 JWT 密钥及明确的跨域来源。

## 本机怎么使用

已启动的新版本：`http://127.0.0.1:8002/`。旧 8000、8001 服务未停止；新版本使用独立的 `var/local-codex/` 数据库，旧进程的内存账户不会自动迁入。

先在新版本注册或登录。通过“用户中心 → 模型 API”填写自己的供应商、Base URL、模型 ID 与 Key，保存后选择“我的 API”即可研究。保存不发模型请求；勾选测试授权后，“测试连接”才会实际请求供应商。

要解锁本机 Codex，需要本机操作者明确选择一个已有用户名后启动：

```powershell
python -m fin_agent.interfaces.local_server --owner 你的已有用户名 --port 8002
```

首次没有账户时，不带 `--owner` 启动并注册：

```powershell
python -m fin_agent.interfaces.local_server --port 8002
```

端口已有新版本进程时，先关闭该进程再用所有者参数重启；不要结束保留旧数据的 8000 服务。启动器仅监听本机，自动生成独立、持久化的登录签名密钥，密钥和数据库都位于 Git 忽略的 `var/local-codex/` 内。该启动器是本机使用入口，不是公开部署方案。

绑定后，指定账户的“模型 API”页出现“本机 Codex · 仅本人使用”：

1. 点击“使用本机 Codex（无需 API Key）”：仅检查登录、选择来源，不调用模型；成功后自动进入金融助手。
2. 确认“研究模型”为“本机 Codex”，输入问题并开始研究。下方其他供应商的 API 表单不用填写。
3. 原有计划、工具选择、报告生成和审查会分别调用模型，完整研究可能消耗多次额度。此入口没有 API 测试所用的 128 token 硬上限；短问题也有 Codex 系统上下文开销。
4. 若只验证连接，勾选授权后点击“真实测试 Codex”，界面显示真实文本、模型和返回的 token 用量。

Codex 使用的是本机用户的 ChatGPT/Codex 额度，不是助手提供的免费 API，也不会为商业客户共享这份额度。

## 新 API 的兼容范围

| 协议 | 适用范围 | 配置注意事项 |
| --- | --- | --- |
| OpenAI Chat Completions | OpenAI、国内兼容接口、Gemini 的兼容接口 | Base URL 不包含 `/chat/completions`；按供应商选择 `max_tokens` 或 `max_completion_tokens` |
| Anthropic Messages | Claude 原生接口及批准的兼容服务 | 使用原生 `x-api-key` 与版本头；Base URL 不包含 `/messages` |
| 其他专有协议 | 本次未实现 | 例如只支持 Responses、AWS 签名鉴权或特殊网关协议的接口需要单独适配 |

自定义地址必须使用 HTTPS、443 端口及管理员的精确域名白名单。扩展 `FIN_AGENT__RUNTIME__LLM_ALLOWED_HOSTS` 时保留原有供应商域名，只追加可信域名；不要为了方便允许任意 URL、内网地址或通配符。接口版本、可用模型和地域权限以对应供应商账户为准。

## 小范围商业化之前

这一版提供了连接方式与初步隔离，不应直接描述为“已经满足收费上线条件”。公开部署至少需要下面的配置：

```dotenv
FIN_AGENT__RUNTIME__COMMERCIAL_MODE=true
FIN_AGENT__RUNTIME__ALLOW_SYSTEM_MODEL=false
FIN_AGENT__CODEX__ENABLED=false
FIN_AGENT__DATABASE__BACKEND=sql
FIN_AGENT__DATABASE__URL=sqlite:///./var/fin_agent.db
FIN_AGENT__RUNTIME__CORS_ORIGINS=["https://your-domain.example"]
# 通过部署环境注入独立随机值，不在仓库中填写真实密钥：
# FIN_AGENT__AUTH__SECRET_KEY=至少32字符的随机密钥
```

还必须完成：HTTPS 与部署密钥管理、登录/注册及研究请求限流、邀请或客户准入、用户级用量与并发控制、备份与删除机制、隐私告知和模型/金融数据的商业使用授权审查。若收费，还需独立设计计费与退款规则。

当前个人 API 密钥只在单个服务进程内存中，宜先用一个 worker；多 worker 需要独立处理会话密钥存储与加密，不能直接扩容后假装连接可共享。浏览器工作区仍按浏览器存储，尚未按登录账户分区；共享设备可能看到此前保存的本地报告，商业试用前需要补齐隔离。现有登录 token 存在浏览器存储中，也需结合正式部署做安全审查。

以上约束不改变当前行情、财务数据接口的实现，也不代表原数据服务已授权商业再分发。量化模块仍是研究与教学原型，没有实盘下单功能。

官方实现参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[账户认证](https://learn.chatgpt.com/docs/auth)、[权限配置](https://learn.chatgpt.com/docs/permissions)。本机安装版本 `0.151.0-alpha.7.2` 的实际协议定义优先于文档中的旧字段。
